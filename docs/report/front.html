Abstract

Large language models can now read an incident's logs, metrics, traces and topology and propose a remediation, but they cannot be trusted to execute it: a fluent, plausible proposal may cordon a healthy node, restart a shared database or switch on a fault-injection flag. This project builds and evaluates sentinel-remediate, a remediation agent in which the LLM is treated strictly as an untrusted planner. Every proposed action passes through a layered pre-execution verifier before it can reach the environment: a deterministic action envelope (allow-list, typed parameters, blast-radius and namespace policy), an independent LLM judge, and a learned, calibrated risk model, combined by a single risk threshold τ that trades safety against autonomy.

The system is built to run end-to-end with no Kubernetes cluster and no API key. It uses an offline environment of {{n_incidents}} incidents — 6 hand-built and 35 converted from IBM's public ITBench-Lite SRE scenarios — with a provenance trail on every ground-truth label. A seeded evaluation harness writes every run to DuckDB and regenerates every table and figure from scratch.

Over {{n_runs}} runs, with τ = 0.5 and a simulated planner, the share of runs in which a destructive action reached execution falls from {{unsafe_none}} (ungated agent) and {{unsafe_env}} (envelope only) to {{unsafe_learned}} with the learned layer, which stops {{residue_caught}} of the destructive proposals that pass the envelope. Escalating every block costs autonomy, but retrying blocked actions with the verifier's reasons restores resolution to {{res_learned_retry}} at {{netsafe_learned_retry}} net-safe resolution, against {{netsafe_none}} for the ungated agent. The report sets these results against a type-only baseline and states the threats to their validity: simulated proposals, rule-derived labels, and curated topology.

Keywords: AIOps, incident remediation, LLM agents, guardrails, pre-execution verification, calibrated risk, safety–autonomy trade-off, ITBench.
