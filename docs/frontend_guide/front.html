How to read this guide

The sentinel-console is the part of the project people actually see. It shows an incident's evidence, lets you start a remediation run, and streams the agent → verifier → executor loop live. Its centrepiece is the layered verdict: every verification layer's decision is shown, not just the final one. It also presents the evaluation results.

The guide builds up in three passes:

  • Chapters 1–5: what the console is and how it is put together. The stack, the folders, where each piece of state lives, and how the same code runs against fake data (mock mode) or the real backend (live mode).
  • Chapters 6–8: what happens on screen and why. Every screen, then the live run step by step, then the VerdictCard in detail.
  • Chapters 9–14: working with the code. The API layer, the generated types, the design rules, recipes for common changes, troubleshooting, and questions to expect in a viva.

File names are given as src/…, relative to frontend/. Each concept links to the file where it lives, so you can read the code alongside.
